DTS decoder plugin (dtsdec) for LG C5 / webOS 25 -- BUILD REPORT
=================================================================

Since webos25-2.43 (app 2.7.38) out/ holds ONE file, libgstdtsdec.so. The
decoder is ffmpeg's dca linked in statically; libdca.so.0 is no longer built or
shipped.

What it decodes
---------------
DTS core, DTS-HD Master Audio lossless (XLL), DTS-HD High Resolution (XBR/X96),
7.1 (XXCH/XLL) and DTS Express (LBR). parse() frames the core together with its
extension substream (EXSS) so both reach the decoder as one packet. Output is
S32LE, up to 8 channels and 192 kHz (src caps channels [1,16], rate
[4000,192000]). The
make-up gain / DRC / centre boost (gain.conf, drc-mode, makeup-gain-db,
center-boost-db) are unchanged; the `drc` boolean property is accepted but is a
no-op (it drove libdca's in-stream DRC).

On-device verification (real LG C5, webOS 10.3.1)
-------------------------------------------------
Output compared against desktop ffmpeg 8.1 decoding the same file:
  DTS-HD MA 5.1 in .mp4            bit-exact, whole file
  DTS-HD MA 5.1 in .ts / .m2ts     bit-exact after GStreamer's normal 40 ms
                                   segment clip at the start (needs the
                                   substream-0x72 tsdemux in ../demux-out/)
  DTS-HD MA 7.1 MKV, 258 s         md5 of the whole decoded stream identical
                                   (73f18659444c14ce83fa664f876b467d),
                                   8 channels, layout 0x63f
Loudness on the 5 main channels is within 0.002 dB of the old libdca decoder
(LFE +1 dB), so the +5 dB default in gain.conf still holds.
CPU: a 3.8 s 5.1 MA file takes 0.37 s user (libdca build: 2.40 s); the 258 s
7.1 MA file decodes in 15.5 s user (~6% of one core).
